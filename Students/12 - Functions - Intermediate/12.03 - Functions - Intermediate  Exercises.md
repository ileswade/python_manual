### Example 1: Building a Flexible Product Pricing System
**Problem:** Create a function `calculate_price` that takes a base price (required), quantity (default 1), discount_percent (default 0), and tax_rate (default 0.05). The function should calculate: subtotal = price × quantity, apply discount, add tax, and return the final total. Demonstrate using positional, named, and mixed arguments.

**Detailed Solution:**

**Step 1: Understand the calculation flow**
1. Subtotal = base_price × quantity
2. Discount amount = subtotal × (discount_percent / 100)
3. After discount = subtotal - discount amount
4. Tax amount = after_discount × tax_rate
5. Final total = after_discount + tax amount

**Step 2: Identify which parameters should have defaults**
- base_price: Required (no default) - must know the price
- quantity: Optional (default 1) - usually buying one item
- discount_percent: Optional (default 0) - not always discounts
- tax_rate: Optional (default 0.05) - standard 5% tax

**Step 3: Plan parameter order**
- Required parameters first: base_price
- Optional parameters after: quantity, discount_percent, tax_rate

**Step 4: Implement with clear logic**

**Complete Solution:**
```python
def calculate_price(base_price, quantity=1, discount_percent=0, tax_rate=0.05):
    """
    Calculate final price with quantity, discount, and tax.
    
    Parameters:
        base_price: Price per item (required)
        quantity: Number of items (default 1)
        discount_percent: Discount as percentage (default 0)
        tax_rate: Tax as decimal (default 0.05 for 5%)
    
    Returns:
        Final price after discount and tax
    """
    # Calculate subtotal
    subtotal = base_price * quantity
    
    # Apply discount
    discount_amount = subtotal * (discount_percent / 100)
    after_discount = subtotal - discount_amount
    
    # Apply tax
    tax_amount = after_discount * tax_rate
    final_total = after_discount + tax_amount
    
    return final_total
```

**Key Concepts:**
- **Parameter order matters**: Required first, optional last

**Why this design works:**

- Named arguments make complex calls self-documenting

### Example 2: Recursive Directory Tree Display
**Problem:** Create a recursive function that displays a nested dictionary structure (simulating a file system) with proper indentation. The dictionary has keys as folder/file names and values as either None (files) or nested dictionaries (folders).

**Detailed Solution:**

**Step 1: Understand the recursive structure**
- Each dictionary is a folder containing items
- Keys are names, values are either None (file) or dict (subfolder)
- Need to indent based on depth level
- Recursion: display folder contents, recurse for subfolders

**Step 2: Identify base and recursive cases**
- Base case: item is a file (value is None) → just display
- Recursive case: item is a folder (value is dict) → display then recurse

**Step 3: Plan the indentation**
- Use level parameter to track depth
- Each level adds indentation (e.g., "  " × level)

**Complete Solution:**
```python
def display_tree(structure, level=0):
    """
    Recursively display nested dictionary as tree structure.
    
    Parameters:
        structure: Dictionary representing folders/files
        level: Current indentation level (default 0)
    """
    indent = "  " * level  # Two spaces per level
    
    for name, content in structure.items():
        if content is None:
            # It's a file
            print(f"{indent}📄 {name}")
        else:
            # It's a folder
            print(f"{indent}📁 {name}/")
            # Recursive call with increased level
            display_tree(content, level + 1)


def count_items(structure):
    """
    Recursively count total files and folders.
    Returns: (file_count, folder_count)
    """
    files = 0
    folders = 0
    
    for name, content in structure.items():
        if content is None:
            files += 1
        else:
            folders += 1
            # Recursive call and add counts
            sub_files, sub_folders = count_items(content)
            files += sub_files
            folders += sub_folders
    
    return files, folders
```

**Key Concepts:**
- **Default parameter for level**: Starts at 0, increases with each recursion
- **Indentation tracking**: level × "  " creates proper nesting
- **Dictionary iteration**: Loop through items to process each
- **Conditional recursion**: Only recurse if value is a dictionary
- **Multiple recursive calls**: Can call recursion multiple times in a loop
- **Return values in recursion**: count_items returns tuple from each level

**Why recursion is perfect here:**
- Tree structures are naturally recursive (folders contain folders)
- Unknown depth - recursion handles any nesting level
- Each folder is processed the same way (recursive pattern)
- Clean code - alternative with loops would be complex

### Example 3: Advanced Fibonacci with Memoization
**Problem:** Create an improved recursive Fibonacci function that uses optional memoization (caching) to avoid recalculating values. Compare performance with and without memoization.

**Detailed Solution:**

**Step 1: Understand the problem**
- Basic Fibonacci recalculates same values many times
- fibonacci(5) calculates fibonacci(3) multiple times
- Memoization: store calculated values, reuse them

**Step 2: Design the solution**
- Add optional memo parameter (default None for no caching)
- If None, use regular recursion
- If dict provided, check cache before calculating
- Store result in cache before returning

**Step 3: Implement with performance tracking**

**Complete Solution:**
```python
import time

def fibonacci_basic(n):
    """Basic recursive Fibonacci (inefficient)."""
    if n == 0:
        return 0
    if n == 1:
        return 1
    return fibonacci_basic(n - 1) + fibonacci_basic(n - 2)


def fibonacci_memo(n, memo=None):
    """
    Fibonacci with optional memoization.
    
    Parameters:
        n: Position in sequence
        memo: Optional dictionary for caching (default None)
    
    Returns:
        nth Fibonacci number
    """
    # Base cases
    if n == 0:
        return 0
    if n == 1:
        return 1
    
    # If memo provided, use caching
    if memo is not None:
        # Check if already calculated
        if n in memo:
            return memo[n]
        
        # Calculate and store
        result = fibonacci_memo(n - 1, memo) + fibonacci_memo(n - 2, memo)
        memo[n] = result
        return result
    
    # No memo - regular recursion
    return fibonacci_memo(n - 1) + fibonacci_memo(n - 2)


def count_calls(n):
    """Count how many function calls are made."""
    call_count = {'count': 0}
    
    def fib_with_counter(n):
        call_count['count'] += 1
        if n == 0:
            return 0
        if n == 1:
            return 1
        return fib_with_counter(n - 1) + fib_with_counter(n - 2)
    
    result = fib_with_counter(n)
    return result, call_count['count']


# Compare performance
print("=== Fibonacci Performance Comparison ===\n")

test_values = [10, 15, 20, 25]

for n in test_values:
    # Basic recursive (no memo)
    start = time.time()
    result1 = fibonacci_memo(n)
    time1 = time.time() - start
    
    # With memoization
    memo = {}
    start = time.time()
    result2 = fibonacci_memo(n, memo)
    time2 = time.time() - start
    
    print(f"fibonacci({n}) = {result1}")
    print(f"  Without memo: {time1:.6f} seconds")
    print(f"  With memo:    {time2:.6f} seconds")
    print(f"  Speedup:      {time1/time2:.1f}x faster")
    print()

# Show call count difference
print("=== Function Call Count ===\n")

for n in [5, 10, 15, 20]:
    result, calls = count_calls(n)
    memo = {}
    _ = fibonacci_memo(n, memo)
    memo_calls = len(memo) + 2  # Approximate for memo version
    
    print(f"fibonacci({n}):")
    print(f"  Without memo: ~{calls} function calls")
    print(f"  With memo:    ~{memo_calls} function calls")
    print()

# Demonstrate memo dictionary contents
print("=== Memoization Cache Contents ===\n")

memo = {}
result = fibonacci_memo(8, memo)

print(f"fibonacci(8) = {result}")
print(f"\nCache contents: {memo}")
print("\nExplanation:")
print("Each calculated value is stored once")
print("Subsequent calls retrieve from cache instantly")
```

**Key Concepts:**
- **Optional memoization**: memo=None means no caching, dict means cache

- **Dictionary as cache**: Keys are inputs, values are results

**Why memoization is powerful:**
- Dramatic performance improvement (1000x+ for large n)
- Prevents redundant calculations
- Uses extra memory to save computation time
- Perfect for overlapping subproblems (like Fibonacci)

## Tips for Solving These Problems

### Named Arguments Strategy
```python
# When calling with many parameters:
# 1. Required parameters first (positional OK)
# 2. Optional parameters by name (clearer)

# Good
create_user("john", "john@email.com", age=25, country="USA")

# Also good - all named for clarity
create_user(
    username="john",
    email="john@email.com",
    age=25,
    country="USA"
)
```

### Default Parameter Design
```python
# Order matters!
def function(required1, required2, optional1=default1, optional2=default2):
    pass

# Always: required first, optional last
# Never: optional before required
```

### Avoiding Mutable Defaults
```python
# WRONG - shared list across calls
def add_item(item, items=[]):
    items.append(item)
    return items

# RIGHT - create new list each time
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

### Recursion Checklist
```python
def recursive_function(n):
    # 1. Base case - MUST HAVE
    if base_condition:
        return base_value
    
    # 2. Recursive case - calls itself
    # 3. Progress toward base case
    return recursive_function(n_modified)
```

### Recursion Patterns

**Pattern 1: Countdown/Count Up**
```python
def count(n):
    if n <= 0:
        return
    print(n)
    count(n - 1)
```

**Pattern 2: Accumulate Result**
```python
def sum_to(n):
    if n == 0:
        return 0
    return n + sum_to(n - 1)
```

**Pattern 3: List Processing**
```python
def process_list(items):
    if not items:
        return []
    return [process(items[0])] + process_list(items[1:])
```

**Pattern 4: Divide and Conquer**
```python
def divide_conquer(data):
    if len(data) <= 1:
        return data
    mid = len(data) // 2
    left = divide_conquer(data[:mid])
    right = divide_conquer(data[mid:])
    return combine(left, right)
```

### Common Recursion Mistakes

**Mistake 1: No base case**
```python
# WRONG - infinite recursion
def count(n):
    print(n)
    count(n - 1)  # Never stops!

# RIGHT - has base case
def count(n):
    if n <= 0:
        return
    print(n)
    count(n - 1)
```

**Mistake 2: Not progressing to base**
```python
# WRONG - never reaches base
def bad_sum(n):
    if n == 0:
        return 0
    return n + bad_sum(n)  # n doesn't change!

# RIGHT - progresses toward base
def good_sum(n):
    if n == 0:
        return 0
    return n + good_sum(n - 1)  # n decreases
```

### Testing Strategy

**Test defaults:**
```python
# Test with no optional args
result1 = function(required_arg)

# Test with some optional args
result2 = function(required_arg, optional1=value)

```

**Test recursion:**
```python
# Test base case directly

# Test one step from base
result2 = recursive_func(1)

# Test normal case
result3 = recursive_func(5)

# Test edge cases

```

### Debugging Recursion
```python
def recursive_func(n, depth=0):
    indent = "  " * depth
    print(f"{indent}Called with n={n}")
    
    if n <= 0:
        print(f"{indent}Base case reached")
        return 0
    
    result = n + recursive_func(n - 1, depth + 1)
    print(f"{indent}Returning {result}")
    return result
```

### When to Use Recursion
- Problem naturally divides into smaller similar problems
- Tree/nested structures (files, directories)
- Mathematical sequences (Fibonacci, factorial)
- Divide and conquer algorithms (merge sort, binary search)

### When NOT to Use Recursion
- Simple iteration would work better
- Performance is critical (recursion has overhead)
- Very deep recursion (risk of stack overflow)
- No natural recursive structure
