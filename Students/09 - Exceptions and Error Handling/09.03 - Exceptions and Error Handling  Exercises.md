### Example 1: Building a Robust Input Validator with Multiple Exception Types
**Problem:** Create a function that asks the user for their age and validates it. The age must be: (1) a valid integer, (2) between 0 and 120, and (3) not negative. Handle ValueError for invalid integers and create custom validation for the range. Keep asking until valid input is received.

**Detailed Solution:**

**Step 1: Identify all possible errors**
- User enters non-numeric text → ValueError
- User enters valid number but < 0 → Custom validation
- User enters valid number but > 120 → Custom validation

**Step 2: Understand the exception flow**
```python
try:
    # Code that might raise exception
except SpecificException:
    # Handle specific error
else:
    # Runs if no exception
finally:
    # Always runs
```

**Step 3: Plan the validation logic**
1. Loop until valid input (while True with break)
2. Try to convert to int (catches ValueError)
3. Validate range (custom checks)
4. Break if all validations pass

**Step 4: Implement with proper error messages**

**Complete Solution:**
```python
def get_valid_age():
    """
    Get valid age from user with comprehensive error handling.
    Returns: Valid age between 0 and 120
    """
    while True:
        try:
            # Get input and convert to integer
            age_input = input("Enter your age: ")
            age = int(age_input)
            
            # Validate range
            if age < 0:
                raise ValueError("Age cannot be negative!")
            
            if age > 120:
                raise ValueError("Age must be 120 or less!")
            
        except ValueError as e:
            # Check if it's our custom error or conversion error
            if "invalid literal" in str(e):
                print("Error: Please enter a valid number!")
            else:
                print(f"Error: {e}")
            
            print("Please try again.\n")
            
        else:
            # Only runs if no exception occurred
            print(f"Valid age received: {age}")
            return age
        
        finally:
            # This runs whether there was an error or not
            # Useful for cleanup or logging
            pass  # Could log attempt here
```

**Key Concepts:**
- **while True + break pattern**: Keeps looping until valid input
- **try-except-else-finally**: Complete exception handling structure
- **else clause**: Runs only if try block succeeds (no exception)
- **finally clause**: Always runs (cleanup code)
- **Raising exceptions manually**: `raise ValueError("message")`
- **Checking exception message**: `if "text" in str(e)`
- **User-friendly error messages**: Tell user what went wrong and how to fix it

**Why this structure works:**
1. try block contains risky code (conversion and validation)
2. except catches both conversion errors and custom validation errors
3. else runs only on success (clean separation)
4. finally runs always (could log attempts, close resources, etc.)
5. Loop continues until break is reached (in else block)

### Example 2: File Operations with Comprehensive Error Handling
**Problem:** Create a function that reads a file and returns its contents. Handle FileNotFoundError, PermissionError, and general IOError. Use the `with` statement for proper file handling. Also create a function that safely writes to a file with backup creation.

**Detailed Solution:**

**Step 1: Understand file-related exceptions**
- **FileNotFoundError**: File doesn't exist
- **PermissionError**: No permission to read/write
- **IOError**: General I/O problems
- **IsADirectoryError**: Trying to open a directory as file

**Step 2: Learn the `with` statement (context manager)**
```python
with open(filename) as file:
    content = file.read()
# File automatically closes, even if exception occurs
```

**Step 3: Plan error handling hierarchy**
Most specific to least specific:
1. FileNotFoundError (specific file issue)
2. PermissionError (specific permission issue)
3. IOError (general I/O issue)

**Step 4: Implement read function**

**Complete Solution:**
```python
def safe_read_file(filename):
    """
    Safely read file contents with error handling.
    
    Returns: (success: bool, content: str, error: str)
    """
    try:
        with open(filename, 'r') as file:
            content = file.read()
            
    except FileNotFoundError:
        return False, None, f"File '{filename}' not found"
        
    except PermissionError:
        return False, None, f"No permission to read '{filename}'"
        
    except IsADirectoryError:
        return False, None, f"'{filename}' is a directory, not a file"
        
    except IOError as e:
        return False, None, f"Error reading file: {e}"
        
    else:
        # Only runs if try block succeeded
        print(f"Successfully read {len(content)} characters from '{filename}'")
        return True, content, None
        
    finally:
        # Always runs - could log attempt here
        print(f"Read attempt for '{filename}' completed")


def safe_write_file(filename, content, create_backup=True):
    """
    Safely write to file with optional backup.
    
    Args:
        filename: File to write to
        content: Content to write
        create_backup: If True, backup existing file first
    
    Returns: (success: bool, error: str)
    """
    import os
    import shutil
    
    backup_file = None
    
    try:
        # Create backup if file exists
        if create_backup and os.path.exists(filename):
            backup_file = filename + '.backup'
            shutil.copy(filename, backup_file)
            print(f"Created backup: {backup_file}")
        
        # Write new content
        with open(filename, 'w') as file:
            file.write(content)
            
    except PermissionError:
        # Restore backup if write failed
        if backup_file and os.path.exists(backup_file):
            shutil.copy(backup_file, filename)
            print("Restored from backup after error")
        return False, f"No permission to write to '{filename}'"
        
    except IOError as e:
        # Restore backup if write failed
        if backup_file and os.path.exists(backup_file):
            shutil.copy(backup_file, filename)
            print("Restored from backup after error")
        return False, f"Error writing file: {e}"
        
    else:
        # Success - remove backup if desired
        print(f"Successfully wrote {len(content)} characters to '{filename}'")
        
        # Optionally remove backup after successful write
        if backup_file and os.path.exists(backup_file):
            # os.remove(backup_file)  # Uncomment to delete backup
            pass
        
        return True, None
        
    finally:
        print(f"Write attempt for '{filename}' completed")
```

**Key Concepts:**
- **with statement (context manager)**: Guarantees file closure
- **Exception hierarchy**: Catch specific before general
- **else clause**: Runs only on success
- **finally clause**: Always runs (logging, cleanup)
- **Backup strategy**: Copy before write, restore on error
- **Tuple returns**: Return multiple values (success, data, error)
- **Resource cleanup**: Files always close with `with`

**The power of `with`:**
```python
# Without with:
file = open("data.txt")
content = file.read()  # If this fails...
file.close()           # ...this never runs!

# With with:
with open("data.txt") as file:
    content = file.read()  # If this fails...
# File STILL closes automatically!
```

### Example 3: Calculator with Complete Error Handling and Input Validation
**Problem:** Build a calculator that handles division by zero, invalid operators, type errors, and keeps running until the user quits. Demonstrate the exception hierarchy by catching parent exceptions appropriately. Show how to use try-except in a menu-driven program.

**Detailed Solution:**

**Step 1: Identify all possible errors**
- Invalid number input → ValueError
- Division by zero → ZeroDivisionError
- Invalid operator → Custom validation
- Unexpected errors → General Exception

**Step 2: Understand exception hierarchy**
```
Exception (parent)
    ├── ArithmeticError
    │   └── ZeroDivisionError
    ├── ValueError
    └── TypeError
```

**Step 3: Plan the calculator structure**
1. Menu loop (while True)
2. Get operator choice
3. Get numbers (with validation)
4. Perform calculation (with error handling)
5. Display result
6. Option to quit

**Step 4: Implement with layered error handling**

**Complete Solution:**
```python
def get_number(prompt):
    """Get a valid number from user."""
    while True:
        try:
            return float(input(prompt))
        except ValueError:
            print("Invalid input! Please enter a number.")


def calculate(num1, operator, num2):
    """
    Perform calculation with error handling.
    
    Returns: (success: bool, result: float, error: str)
    """
    try:
        if operator == '+':
            result = num1 + num2
        elif operator == '-':
            result = num1 - num2
        elif operator == '*':
            result = num1 * num2
        elif operator == '/':
            result = num1 / num2
        elif operator == '**':
            result = num1 ** num2
        elif operator == '%':
            result = num1 % num2
        else:
            return False, None, f"Unknown operator: {operator}"
            
    except ZeroDivisionError:
        return False, None, "Cannot divide by zero!"
        
    except OverflowError:
        return False, None, "Result too large to calculate!"
        
    except Exception as e:
        return False, None, f"Calculation error: {e}"
        
    else:
        return True, result, None


def calculator():
    """Main calculator with comprehensive error handling."""
    
    print("=== Advanced Calculator ===")
    print("Operators: +, -, *, /, **, %")
    print("Type 'quit' to exit\n")
    
    while True:
        try:
            # Get operator
            operator = input("Enter operator (or 'quit'): ").strip()
            
            if operator.lower() == 'quit':
                print("Thank you for using the calculator!")
                break
            
            # Validate operator
            valid_operators = ['+', '-', '*', '/', '**', '%']
            if operator not in valid_operators:
                print(f"Invalid operator! Use: {', '.join(valid_operators)}\n")
                continue
            
            # Get numbers
            try:
                num1 = get_number("Enter first number: ")
                num2 = get_number("Enter second number: ")
            except KeyboardInterrupt:
                print("\n\nOperation cancelled.")
                continue
            
            # Perform calculation
            success, result, error = calculate(num1, operator, num2)
            
            if success:
                print(f"\nResult: {num1} {operator} {num2} = {result}\n")
            else:
                print(f"\nError: {error}\n")
                
        except KeyboardInterrupt:
            print("\n\nCalculator interrupted. Type 'quit' to exit.\n")
            
        except Exception as e:
            print(f"\nUnexpected error: {e}")
            print("Please try again.\n")
```

## Tips for Solving These Problems

### Understanding Try-Except Structure
```python
try:
    # Code that might raise exception
    risky_operation()
except SpecificException:
    # Handle specific error
    handle_error()
except AnotherException:
    # Handle different error
    handle_different_error()
else:
    # Runs only if NO exception
    success_code()
finally:
    # ALWAYS runs
    cleanup_code()
```

### Common Exception Types
1. **ValueError**: Wrong value (e.g., int("hello"))
2. **TypeError**: Wrong type (e.g., "5" + 5)
3. **ZeroDivisionError**: Division by zero
4. **IndexError**: Invalid list index
5. **KeyError**: Invalid dictionary key
6. **FileNotFoundError**: File doesn't exist
7. **PermissionError**: No permission to access
8. **NameError**: Undefined variable
9. **AttributeError**: Invalid attribute

### Exception Handling Patterns

**Pattern 1: Simple validation**
```python
try:
    value = int(input("Enter number: "))
except ValueError:
    print("Not a valid number!")
```

**Pattern 2: Input loop**
```python
while True:
    try:
        value = int(input("Enter number: "))
        break  # Exit on success
    except ValueError:
        print("Try again!")
```

**Pattern 3: File operations**
```python
try:
    with open("file.txt") as f:
        content = f.read()
except FileNotFoundError:
    print("File not found!")
```

**Pattern 4: Multiple exceptions**
```python
try:
    result = int(input()) / int(input())
except ValueError:
    print("Invalid number!")
except ZeroDivisionError:
    print("Cannot divide by zero!")
```

### When to Use Each Clause

**Use try:** Always - contains risky code

**Use except:** Always - handles errors
- Catch specific exceptions first
- Then catch general exceptions
- Don't use bare `except:` without type

**Use else:** Optional - success code
- Runs only if no exception
- Keeps try block minimal
- Separates error handling from success logic

**Use finally:** Optional - cleanup code
- Always runs (error or not)
- Close files, release resources
- Log attempts, update status

### Best Practices
1. **Catch specific exceptions** - not bare `except:`
2. **Order matters** - specific before general
3. **Keep try block small** - only risky code
4. **Provide helpful messages** - tell user what went wrong
5. **Don't hide errors** - log or handle properly
6. **Use else for success** - separates concerns
7. **Use finally for cleanup** - guaranteed execution
8. **Don't catch what you can't handle** - let it propagate

```
    │   ├── OverflowError
```

### Raising Exceptions
```python

# Re-raise caught exception
```

### Input Validation Pattern

```python
                return value
```

1. **Print exception details:**


2. **Check exception hierarchy:**

3. **Test error cases:**
   ```python
   # Test each exception path
   ```

4. **Use else to verify:**
   ```python

   ```

### Common Mistakes to Avoid
1. **Bare except** - catches everything, even Ctrl+C
   ```python
   # Bad
   except:
       pass
   
   # Good
   except ValueError:
       pass
   ```

2. **Wrong order** - general before specific
   ```python
   # Bad - Exception catches everything
   except Exception:
       ...
   except ValueError:  # Never reached!
       ...
   ```

3. **Silent failures** - hiding errors
   ```python
   # Bad
   except:
       pass  # Error disappears!
   
   # Good
   except ValueError as e:
       print(f"Error: {e}")
   ```

4. **Forgetting to break** - infinite validation loops
   ```python
   # Bad
   while True:
       try:
           value = int(input())
       except ValueError:
           print("Try again")
       # No break! Loops forever
   ```
