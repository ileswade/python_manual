# What is an Exception? 🤔

An **exception** is an error that occurs during program execution. When Python encounters a problem it can't handle, it "raises" (throws) an exception.

<v-clicks>

```python
# This causes an exception
number = int("hello")  # ValueError: invalid literal for int()
```

**What happens without exception handling:**
1. Python encounters an error
2. Raises an exception
3. Prints error message
4. **Program crashes and stops** 💥

</v-clicks>

<v-click>

<div class="mt-6 p-4 bg-red-100 dark:bg-red-900 rounded">
⚠️ <strong>The Problem:</strong> One small error can crash your entire program, losing user data and creating a poor experience.
</div>

</v-click>

# Common Exception Types 📚

Python has many built-in exception types. Here are the most common ones you'll encounter:

<div class="grid grid-cols-2 gap-4 text-sm">

<div>

<v-click>

### ValueError
Wrong type, right value
```python
int("abc")  # Can't convert "abc" to int
```

### TypeError
Wrong type for operation
```python
"hello" + 5  # Can't add string and int
```

### ZeroDivisionError
Division by zero
```python
10 / 0  # Math error!
```

### IndexError
Invalid list index
```python
[1, 2, 3][5]  # Index 5 doesn't exist
```

</v-click>

</div>

<div>

<v-click>

### FileNotFoundError
File doesn't exist
```python
open("missing.txt")  # File not found
```

### KeyError
Invalid dictionary key
```python
{"name": "Alice"}["age"]  # Key doesn't exist
```

### NameError
Undefined variable
```python
print(undefined_var)  # Variable doesn't exist
```

### AttributeError
Invalid attribute/method
```python
"hello".append("!")  # Strings don't have append
```

</v-click>

</div>

</div>

# Try-Except Blocks: Graceful Error Handling 🛡️

**Try-except blocks** let you handle exceptions gracefully instead of crashing.

<v-clicks>

### Basic Try-Except

```python
try:
    # Code that might cause an exception
    number = int(input("Enter a number: "))
    print(f"You entered: {number}")
except:
    # Code that runs if ANY exception occurs
    print("That's not a valid number!")
```

**How it works:**
1. Python tries to run code in the `try` block
2. If an exception occurs, jump to `except` block
3. Program continues running (doesn't crash!) ✨

</v-clicks>

---

# Catching Specific Exceptions 🎯

It's much better to catch **specific exception types**:

<v-clicks>

```python
try:
    number = int(input("Enter a number: "))
    result = 10 / number
    print(f"Result: {result}")
except ValueError:
    print("That's not a valid number!")
except ZeroDivisionError:
    print("Cannot divide by zero!")
```

**Why catch specific exceptions?**
- Different errors need different handling
- More precise error messages for users
- Unexpected errors still crash (good for debugging!)

</v-clicks>

<v-click>

### Multiple Exceptions in One Block

```python
try:
    number = int(input("Enter a number: "))
    result = 10 / number
except (ValueError, ZeroDivisionError):
    print("Invalid input or cannot divide by zero!")
```

</v-click>

---

# The Else Clause: Success Path 🌟

The `else` clause runs if **NO exception occurred**:

<v-clicks>

```python
try:
    number = int(input("Enter a number: "))
except ValueError:
    print("Invalid number!")
else:
    # Only runs if no exception
    print(f"Success! You entered {number}")
    if number > 0:
        print("That's a positive number!")
```

**When to use `else`:**
- Code that should only run if `try` succeeds
- Keeps `try` block minimal (best practice)
- Makes the success path clear and separate

</v-clicks>

---

# The Finally Clause: Always Runs 🔄

The `finally` clause **always runs**, whether an exception occurred or not:

<v-clicks>

```python
try:
    number = int(input("Enter a number: "))
    result = 10 / number
    print(f"Result: {result}")
except ValueError:
    print("Invalid number!")
except ZeroDivisionError:
    print("Cannot divide by zero!")
finally:
    print("This ALWAYS runs!")
```

**When to use `finally`:**
- Cleanup code (close files, release resources)
- Code that must run no matter what happens
- Logging or tracking operations

</v-clicks>

# Getting Exception Details 🔍

### Accessing the Exception Object

<v-clicks>

```python
try:
    number = int(input("Enter a number: "))
except ValueError as e:
    print(f"Error occurred: {e}")
    print(f"Error type: {type(e).__name__}")
```

**Output if user enters "abc":**
```
Error occurred: invalid literal for int() with base 10: 'abc'
Error type: ValueError
```

This gives you detailed information about what went wrong!

</v-clicks>

# Practical Example: Safe Input Function 🛠️

<v-clicks>

```python
def get_integer(prompt):
    """Get integer input with error handling."""
    while True:
        try:
            value = int(input(prompt))
            return value
        except ValueError as e:
            print(f"Invalid input: {e}")
            print("Please enter a valid integer.")

# Use the function
age = get_integer("Enter your age: ")
print(f"You are {age} years old")
```

This function keeps asking until the user enters a valid integer. No more crashes from invalid input!

</v-clicks>

# Raising Your Own Exceptions 🚀

You can **raise** (throw) your own exceptions when you detect problems:

<v-clicks>

```python
def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative!")
    if age > 150:
        raise ValueError("Age seems unrealistic!")
    return age

try:
    user_age = set_age(-5)
except ValueError as e:
    print(f"Error: {e}")
```

**Output:** `Error: Age cannot be negative!`

This lets you create custom validation with meaningful error messages.

</v-clicks>

# Exception Hierarchy: Family Tree 🌳

Python exceptions are organized in a **hierarchy**. Catching a parent exception catches all child exceptions.

<v-clicks>

```
BaseException
    |
    +-- Exception
            |
            +-- ValueError
            +-- TypeError
            +-- ArithmeticError
            |       |
            |       +-- ZeroDivisionError
            |
            +-- LookupError
            |       |
            |       +-- IndexError
            |       +-- KeyError
            |
            +-- OSError
                    |
                    +-- FileNotFoundError
```

</v-clicks>

# Using the Exception Hierarchy 🎯

### Catching Related Exceptions

<v-clicks>

```python
try:
    numbers = [1, 2, 3]
    index = int(input("Enter index: "))
    print(numbers[index])
except LookupError:  # Catches both IndexError and KeyError
    print("Invalid index or key!")
except ValueError:
    print("Not a valid number!")
```

### Order Matters!

```python
# ✅ CORRECT - specific first
try:
    # some code
except ValueError:      # Specific exception first
    print("Value error")
except Exception:       # General exception last
    print("Some other error")

# ❌ WRONG - general first catches everything
try:
    # some code
except Exception:       # This catches EVERYTHING
    print("Some error")
except ValueError:      # Never reached!
    print("Value error")
```

</v-clicks>

# Context Managers: Safe Resource Handling 🔐

### The Problem with Resources

<v-clicks>

```python
# The problem: resource might not be released
file = open("data.txt", "r")
content = file.read()  # If this raises an exception...
file.close()           # ...this never runs!
```

If an exception occurs, the file stays open, wasting system resources.

</v-clicks>

<v-click>

### The Solution: Context Managers (`with` statement)

```python
with open("data.txt", "r") as file:
    content = file.read()
    # Process content
# File automatically closes here, even if exception occurs!
```

**How it works:**
1. `with` statement enters a context
2. Resource is acquired (file opened)
3. Your code runs in the indented block
4. Context manager ensures cleanup (file closed), **even if exception occurs**
5. Exception propagates normally after cleanup

</v-clicks>

---

# Why Context Managers Matter 💡

<v-clicks>

**Context managers guarantee:**
1. **Setup code runs** when entering context
2. **Cleanup code runs** when exiting context
3. **Cleanup happens even with exceptions**
4. **Exceptions still propagate** after cleanup

**Use context managers for:**
- Opening files
- Database connections
- Network sockets
- Thread locks
- Any resource that needs cleanup

</v-clicks>

<v-click>

**Remember:** The `with` statement isn't just about files—it's about **automatic resource management with exception safety**!

</v-click>

# Practical Examples: Real-World Error Handling 🌍

### Example 1: Safe Division Calculator

<v-clicks>

```python
def safe_divide():
    """Calculator that handles all division errors."""
    try:
        num1 = float(input("Enter first number: "))
        num2 = float(input("Enter second number: "))
        result = num1 / num2
    except ValueError:
        print("Error: Please enter valid numbers!")
        return None
    except ZeroDivisionError:
        print("Error: Cannot divide by zero!")
        return None
    else:
        print(f"Result: {result}")
        return result
    finally:
        print("Calculation attempt complete.")

safe_divide()
```

</v-clicks>

# Example 2: File Processing with Error Handling 📁

<v-clicks>

```python
def process_data_file(filename):
    """Process data file with comprehensive error handling."""
    try:
        with open(filename, "r") as file:
            for line_number, line in enumerate(file, 1):
                try:
                    # Process each line
                    value = float(line.strip())
                    print(f"Line {line_number}: {value}")
                except ValueError:
                    print(f"Warning: Invalid data on line {line_number}: '{line.strip()}'")
                    continue
    except FileNotFoundError:
        print(f"Error: File '{filename}' not found!")
    except PermissionError:
        print(f"Error: No permission to read '{filename}'!")
    except Exception as e:
        print(f"Unexpected error: {e}")

process_data_file("data.txt")
```

This shows layered error handling - file-level AND line-level errors are handled gracefully.

</v-clicks>

# Example 3: Input Validation Loop 🔄

<v-clicks>

```python
def get_positive_integer(prompt):
    """Get positive integer with comprehensive validation."""
    while True:
        try:
            value = int(input(prompt))
            if value <= 0:
                raise ValueError("Number must be positive!")
            return value
        except ValueError as e:
            if "invalid literal" in str(e):
                print("Error: Please enter a valid integer!")
            else:
                print(f"Error: {e}")
            print("Please try again.")

# Usage
age = get_positive_integer("Enter your age (must be positive): ")
print(f"Your age: {age}")
```

This combines exception handling with custom validation logic.

# Best Practices: Do's and Don'ts ✅❌

<div class="grid grid-cols-2 gap-6 text-sm">

<div>

<v-click>

### ✅ Do's

**Catch specific exceptions:**
```python
except ValueError:  # Good
    ...
```

**Keep try blocks small:**
```python
try:
    risky_operation()  # Only risky code
except ValueError:
    ...
# Safe code goes outside
```

**Provide helpful messages:**
```python
except ValueError as e:
    print(f"Invalid input: {e}")
    print("Please enter a number 1-100")
```

</v-click>

</div>

<div>

<v-click>

### ❌ Don'ts

**Don't use bare except:**
```python
except:  # Bad - catches everything!
    ...
```

**Don't hide errors silently:**
```python
try:
    risky_operation()
except:
    pass  # Bad - errors disappear!
```

**Don't catch what you can't handle:**
```python
except Exception as e:
    print("Something went wrong")  # Too vague!
```

</v-click>

</div>

</div>

# When to Use Exception Handling 🤷‍♂️

<div class="grid grid-cols-2 gap-6">

<div>

<v-click>

### ✅ Use Exception Handling When:

1. **User input is involved**
2. **File operations**
3. **Network operations**
4. **Type conversions**
5. **External resources**

```python
# Good use case
try:
    age = int(input("Enter age: "))
except ValueError:
    print("Invalid age!")
```

</v-click>

</div>

<div>

<v-click>

### ❌ Don't Use Exception Handling When:

1. **You can check beforehand**
2. **Logic errors (bugs)**
3. **Normal control flow**

```python
# Bad - check first instead
if len(my_list) > 5:
    value = my_list[5]

# Good - no exception needed
```

</v-click>
