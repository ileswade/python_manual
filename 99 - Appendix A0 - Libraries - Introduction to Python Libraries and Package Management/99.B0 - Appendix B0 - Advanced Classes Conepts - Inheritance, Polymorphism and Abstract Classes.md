## 1. Understanding Inheritance

**Inheritance** allows a class to inherit attributes and methods from another class. Think of it like genetics - children inherit traits from their parents, but can also have their own unique characteristics.

### The Basic Concept

```python
# Parent class (Base class, Superclass)
class Animal:
    def __init__(self, name):
        self.name = name
    
    def speak(self):
        print(f"{self.name} makes a sound")

# Child class (Derived class, Subclass)
class Dog(Animal):
    def bark(self):
        print(f"{self.name} barks: Woof!")

# Dog inherits from Animal
dog = Dog("Buddy")
dog.speak()  # Inherited method: Buddy makes a sound
dog.bark()   # Own method: Buddy barks: Woof!
```

**Key observations:**
- `Dog(Animal)` means Dog inherits from Animal
- Dog automatically gets all of Animal's methods
- Dog can add its own methods
- This creates an "is-a" relationship: A dog IS AN animal

### Why Use Inheritance?

**Code reuse:** Write common functionality once in the parent class

```python
class Vehicle:
    def __init__(self, make, model):
        self.make = make
        self.model = model
    
    def start(self):
        print(f"{self.make} {self.model} is starting")

class Car(Vehicle):
    def honk(self):
        print("Beep beep!")

class Motorcycle(Vehicle):
    def wheelie(self):
        print("Doing a wheelie!")

car = Car("Toyota", "Camry")
car.start()  # Inherited
car.honk()   # Own method

bike = Motorcycle("Harley", "Street 750")
bike.start()   # Inherited
bike.wheelie() # Own method
```

Both Car and Motorcycle get `start()` for free from Vehicle!

### The `super()` Function

`super()` gives access to the parent class's methods:

```python
class Animal:
    def __init__(self, name):
        self.name = name
        print(f"Animal __init__ called for {name}")

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)  # Call parent's __init__
        self.breed = breed
        print(f"Dog __init__ called for {name}")

dog = Dog("Buddy", "Golden Retriever")
# Output:
# Animal __init__ called for Buddy
# Dog __init__ called for Buddy
```

**Without `super()`**, the parent's `__init__` wouldn't run, and `self.name` wouldn't be set!

## 2. Method Overriding

**Method overriding** means a child class replaces a parent's method with its own version.

### Basic Override

```python
class Animal:
    def speak(self):
        print("Some generic animal sound")

class Dog(Animal):
    def speak(self):  # Override parent's speak
        print("Woof!")

class Cat(Animal):
    def speak(self):  # Override parent's speak
        print("Meow!")

# Each class has its own version of speak
dog = Dog()
dog.speak()  # Woof!

cat = Cat()
cat.speak()  # Meow!
```

### Extending Parent Methods with `super()`

Sometimes you want to keep the parent's behavior AND add more:

```python
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary
    
    def give_raise(self, amount):
        self.salary += amount
        print(f"{self.name}'s new salary: ${self.salary}")

class Manager(Employee):
    def __init__(self, name, salary, department):
        super().__init__(name, salary)
        self.department = department
    
    def give_raise(self, amount):
        super().give_raise(amount)  # Call parent's version
        print(f"Manager of {self.department} department")

manager = Manager("Alice", 80000, "Engineering")
manager.give_raise(5000)
# Alice's new salary: $85000
# Manager of Engineering department
```

### Common Override: `__str__` and `__repr__`

```python
class Shape:
    def __init__(self, color):
        self.color = color
    
    def __str__(self):
        return f"A {self.color} shape"

class Circle(Shape):
    def __init__(self, color, radius):
        super().__init__(color)
        self.radius = radius
    
    def __str__(self):
        return f"A {self.color} circle with radius {self.radius}"

circle = Circle("red", 5)
print(circle)  # A red circle with radius 5
```

## 3. Polymorphism

**Polymorphism** means "many forms." In programming, it means objects of different classes can be treated the same way if they share a common interface.

### The Core Idea

```python
class Animal:
    def speak(self):
        pass

class Dog(Animal):
    def speak(self):
        return "Woof!"

class Cat(Animal):
    def speak(self):
        return "Meow!"

class Bird(Animal):
    def speak(self):
        return "Tweet!"

# Polymorphism in action
animals = [Dog(), Cat(), Bird()]

for animal in animals:
    print(animal.speak())  # Each responds differently

# Output:
# Woof!
# Meow!
# Tweet!
```

**The power:** We treat all animals the same way (call `speak()`), but each responds according to its type.

### Practical Example: Shape Area Calculator

```python
class Shape:
    def area(self):
        pass
    
    def __str__(self):
        return "Generic shape"

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height
    
    def area(self):
        return self.width * self.height
    
    def __str__(self):
        return f"Rectangle ({self.width}x{self.height})"

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius
    
    def area(self):
        return 3.14159 * self.radius ** 2
    
    def __str__(self):
        return f"Circle (radius: {self.radius})"

# Polymorphism: treat different shapes the same way
shapes = [
    Rectangle(5, 10),
    Circle(7),
    Rectangle(3, 3)
]

for shape in shapes:
    print(f"{shape}: Area = {shape.area()}")

# Output:
# Rectangle (5x10): Area = 50
# Circle (radius: 7): Area = 153.93791
# Rectangle (3x3): Area = 9
```

### Duck Typing in Python

Python uses "duck typing": "If it walks like a duck and quacks like a duck, it's a duck."

You don't need inheritance for polymorphism in Python:

```python
class Dog:
    def speak(self):
        return "Woof!"

class Robot:
    def speak(self):
        return "Beep boop!"

# No common parent, but both have speak()
things = [Dog(), Robot()]

for thing in things:
    print(thing.speak())  # Works!
```

**However**, inheritance makes relationships explicit and clearer.

## 4. Abstract Classes

**Abstract classes** are templates that can't be instantiated. They force child classes to implement certain methods.

### Why Abstract Classes?

Sometimes you want to ensure all child classes have specific methods:

```python
# Without abstract class - no enforcement
class Shape:
    def area(self):
        pass  # Easy to forget to override

class Rectangle(Shape):
    pass  # Oops, forgot to implement area!

rect = Rectangle()
rect.area()  # Returns None, no error!
```

### Creating Abstract Classes

Use the `abc` module (Abstract Base Classes):

```python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass
    
    @abstractmethod
    def perimeter(self):
        pass

# This will cause an error:
# shape = Shape()  # TypeError: Can't instantiate abstract class

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height
    
    def area(self):
        return self.width * self.height
    
    def perimeter(self):
        return 2 * (self.width + self.height)

# This works - all abstract methods implemented
rect = Rectangle(5, 10)
print(rect.area())  # 50
```

### Abstract Methods with Implementation

Abstract methods can have default implementations:

```python
from abc import ABC, abstractmethod

class Animal(ABC):
    def __init__(self, name):
        self.name = name
    
    @abstractmethod
    def speak(self):
        return f"{self.name} makes a sound"

class Dog(Animal):
    def speak(self):
        parent_sound = super().speak()
        return f"{parent_sound}: Woof!"

dog = Dog("Buddy")
print(dog.speak())  # Buddy makes a sound: Woof!
```

### Practical Example: Payment System

```python
from abc import ABC, abstractmethod

class PaymentMethod(ABC):
    @abstractmethod
    def process_payment(self, amount):
        pass
    
    @abstractmethod
    def refund(self, amount):
        pass

class CreditCard(PaymentMethod):
    def __init__(self, card_number):
        self.card_number = card_number
    
    def process_payment(self, amount):
        print(f"Processing ${amount} via Credit Card {self.card_number[-4:]}")
        return True
    
    def refund(self, amount):
        print(f"Refunding ${amount} to Credit Card")
        return True

class PayPal(PaymentMethod):
    def __init__(self, email):
        self.email = email
    
    def process_payment(self, amount):
        print(f"Processing ${amount} via PayPal ({self.email})")
        return True
    
    def refund(self, amount):
        print(f"Refunding ${amount} to PayPal")
        return True

# Use polymorphism
def checkout(payment_method, amount):
    if payment_method.process_payment(amount):
        print("Payment successful!")

credit = CreditCard("1234567890123456")
paypal = PayPal("user@email.com")

checkout(credit, 99.99)
checkout(paypal, 49.99)
```

## 5. Multiple Inheritance

Python supports **multiple inheritance** - a class can inherit from multiple parents.

### Basic Multiple Inheritance

```python
class Flyer:
    def fly(self):
        print("Flying through the air")

class Swimmer:
    def swim(self):
        print("Swimming through water")

class Duck(Flyer, Swimmer):
    def quack(self):
        print("Quack!")

duck = Duck()
duck.fly()   # From Flyer
duck.swim()  # From Swimmer
duck.quack() # Own method
```

### Method Resolution Order (MRO)

When a method exists in multiple parents, Python uses MRO to decide which to use:

```python
class A:
    def method(self):
        print("Method from A")

class B:
    def method(self):
        print("Method from B")

class C(A, B):
    pass

obj = C()
obj.method()  # Method from A (first parent)

# See the MRO
print(C.mro())
# [<class '__main__.C'>, <class '__main__.A'>, <class '__main__.B'>, <class 'object'>]
```

Python checks: C → A → B → object

### The Diamond Problem

```python
class A:
    def method(self):
        print("A")

class B(A):
    def method(self):
        print("B")

class C(A):
    def method(self):
        print("C")

class D(B, C):
    pass

d = D()
d.method()  # What gets called?

# Check MRO
print(D.mro())
# [D, B, C, A, object]
# So B's method gets called
```

### When to Use Multiple Inheritance

**Use sparingly!** Multiple inheritance can get complex. Better alternatives:
- **Composition** (has-a relationships)
- **Mixins** (small classes that add functionality)

```python
# Mixin example
class JSONMixin:
    def to_json(self):
        import json
        return json.dumps(self.__dict__)

class User(JSONMixin):
    def __init__(self, name, email):
        self.name = name
        self.email = email

user = User("Alice", "alice@email.com")
print(user.to_json())  # {"name": "Alice", "email": "alice@email.com"}
```

## 6. Design Pattern: Factory Pattern

The **Factory Pattern** creates objects without specifying their exact class.

### The Problem

```python
# Tightly coupled code
def create_animal(animal_type, name):
    if animal_type == "dog":
        return Dog(name)
    elif animal_type == "cat":
        return Cat(name)
    elif animal_type == "bird":
        return Bird(name)
    # Adding new animals requires modifying this function
```

### Factory Pattern Solution

```python
from abc import ABC, abstractmethod

class Animal(ABC):
    def __init__(self, name):
        self.name = name
    
    @abstractmethod
    def speak(self):
        pass

class Dog(Animal):
    def speak(self):
        return f"{self.name} says: Woof!"

class Cat(Animal):
    def speak(self):
        return f"{self.name} says: Meow!"

class Bird(Animal):
    def speak(self):
        return f"{self.name} says: Tweet!"

class AnimalFactory:
    @staticmethod
    def create_animal(animal_type, name):
        if animal_type == "dog":
            return Dog(name)
        elif animal_type == "cat":
            return Cat(name)
        elif animal_type == "bird":
            return Bird(name)
        else:
            raise ValueError(f"Unknown animal type: {animal_type}")

# Use the factory
animals = [
    AnimalFactory.create_animal("dog", "Buddy"),
    AnimalFactory.create_animal("cat", "Whiskers"),
    AnimalFactory.create_animal("bird", "Tweety")
]

for animal in animals:
    print(animal.speak())
```

### Advanced Factory with Registry

```python
class ShapeFactory:
    _shapes = {}
    
    @classmethod
    def register_shape(cls, name, shape_class):
        cls._shapes[name] = shape_class
    
    @classmethod
    def create_shape(cls, name, *args, **kwargs):
        if name not in cls._shapes:
            raise ValueError(f"Unknown shape: {name}")
        return cls._shapes[name](*args, **kwargs)

# Register shapes
class Circle:
    def __init__(self, radius):
        self.radius = radius

class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

ShapeFactory.register_shape("circle", Circle)
ShapeFactory.register_shape("rectangle", Rectangle)

# Create shapes
circle = ShapeFactory.create_shape("circle", 5)
rect = ShapeFactory.create_shape("rectangle", 10, 20)
```

## 7. Design Pattern: Strategy Pattern

The **Strategy Pattern** defines a family of algorithms and makes them interchangeable.

### Example: Sorting Strategies

```python
from abc import ABC, abstractmethod

class SortStrategy(ABC):
    @abstractmethod
    def sort(self, data):
        pass

class BubbleSort(SortStrategy):
    def sort(self, data):
        print("Sorting using Bubble Sort")
        # Simplified bubble sort
        for i in range(len(data)):
            for j in range(len(data) - 1):
                if data[j] > data[j + 1]:
                    data[j], data[j + 1] = data[j + 1], data[j]
        return data

class QuickSort(SortStrategy):
    def sort(self, data):
        print("Sorting using Quick Sort")
        if len(data) <= 1:
            return data
        pivot = data[len(data) // 2]
        left = [x for x in data if x < pivot]
        middle = [x for x in data if x == pivot]
        right = [x for x in data if x > pivot]
        return self.sort(left) + middle + self.sort(right)

class Sorter:
    def __init__(self, strategy):
        self.strategy = strategy
    
    def set_strategy(self, strategy):
        self.strategy = strategy
    
    def sort(self, data):
        return self.strategy.sort(data)

# Use different strategies
data = [64, 34, 25, 12, 22, 11, 90]

sorter = Sorter(BubbleSort())
print(sorter.sort(data.copy()))

sorter.set_strategy(QuickSort())
print(sorter.sort(data.copy()))
```

### Practical Example: Payment Strategies

```python
from abc import ABC, abstractmethod

class PaymentStrategy(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

class CreditCardPayment(PaymentStrategy):
    def __init__(self, card_number, cvv):
        self.card_number = card_number
        self.cvv = cvv
    
    def pay(self, amount):
        print(f"Paid ${amount} using Credit Card ending in {self.card_number[-4:]}")

class PayPalPayment(PaymentStrategy):
    def __init__(self, email):
        self.email = email
    
    def pay(self, amount):
        print(f"Paid ${amount} using PayPal account {self.email}")

class CryptoPayment(PaymentStrategy):
    def __init__(self, wallet_address):
        self.wallet_address = wallet_address
    
    def pay(self, amount):
        print(f"Paid ${amount} using Crypto wallet {self.wallet_address[:10]}...")

class ShoppingCart:
    def __init__(self):
        self.items = []
        self.payment_strategy = None
    
    def add_item(self, item, price):
        self.items.append({"item": item, "price": price})
    
    def set_payment_method(self, strategy):
        self.payment_strategy = strategy
    
    def checkout(self):
        total = sum(item["price"] for item in self.items)
        if self.payment_strategy:
            self.payment_strategy.pay(total)
        else:
            print("No payment method set!")

# Use the cart
cart = ShoppingCart()
cart.add_item("Laptop", 999.99)
cart.add_item("Mouse", 29.99)

# Pay with credit card
cart.set_payment_method(CreditCardPayment("1234567890123456", "123"))
cart.checkout()

# Change to PayPal
cart.set_payment_method(PayPalPayment("user@email.com"))
cart.checkout()
```

## 8. Design Pattern: Observer Pattern

The **Observer Pattern** allows objects to notify other objects about changes in their state.

### Implementation

```python
from abc import ABC, abstractmethod

class Observer(ABC):
    @abstractmethod
    def update(self, message):
        pass

class Subject:
    def __init__(self):
        self._observers = []
    
    def attach(self, observer):
        if observer not in self._observers:
            self._observers.append(observer)
    
    def detach(self, observer):
        self._observers.remove(observer)
    
    def notify(self, message):
        for observer in self._observers:
            observer.update(message)

# Concrete observers
class EmailNotifier(Observer):
    def __init__(self, email):
        self.email = email
    
    def update(self, message):
        print(f"Email to {self.email}: {message}")

class SMSNotifier(Observer):
    def __init__(self, phone):
        self.phone = phone
    
    def update(self, message):
        print(f"SMS to {phone}: {message}")

class PushNotifier(Observer):
    def __init__(self, device_id):
        self.device_id = device_id
    
    def update(self, message):
        print(f"Push notification to device {self.device_id}: {message}")

# Concrete subject
class NewsPublisher(Subject):
    def publish_news(self, headline):
        print(f"\nPublishing: {headline}")
        self.notify(headline)

# Use the observer pattern
publisher = NewsPublisher()

email_notifier = EmailNotifier("user@email.com")
sms_notifier = SMSNotifier("555-1234")
push_notifier = PushNotifier("device123")

publisher.attach(email_notifier)
publisher.attach(sms_notifier)
publisher.attach(push_notifier)

publisher.publish_news("Breaking News: Python 4.0 Released!")
# All observers get notified

publisher.detach(sms_notifier)
publisher.publish_news("Python 4.1 Coming Soon")
# SMS notifier doesn't get this one
```

## 9. Putting It All Together: Complete Example

```python
from abc import ABC, abstractmethod
from enum import Enum

class EmployeeType(Enum):
    FULL_TIME = "full_time"
    PART_TIME = "part_time"
    CONTRACT = "contract"

class Employee(ABC):
    employee_count = 0
    
    def __init__(self, name, employee_id):
        self.name = name
        self.employee_id = employee_id
        Employee.employee_count += 1
    
    @abstractmethod
    def calculate_pay(self):
        pass
    
    @abstractmethod
    def get_benefits(self):
        pass
    
    def __str__(self):
        return f"{self.__class__.__name__}: {self.name} (ID: {self.employee_id})"

class FullTimeEmployee(Employee):
    def __init__(self, name, employee_id, annual_salary):
        super().__init__(name, employee_id)
        self.annual_salary = annual_salary
    
    def calculate_pay(self):
        return self.annual_salary / 12
    
    def get_benefits(self):
        return ["Health Insurance", "401k", "Paid Time Off"]

class PartTimeEmployee(Employee):
    def __init__(self, name, employee_id, hourly_rate, hours_worked):
        super().__init__(name, employee_id)
        self.hourly_rate = hourly_rate
        self.hours_worked = hours_worked
    
    def calculate_pay(self):
        return self.hourly_rate * self.hours_worked
    
    def get_benefits(self):
        return ["Flexible Schedule"]

class ContractEmployee(Employee):
    def __init__(self, name, employee_id, contract_amount):
        super().__init__(name, employee_id)
        self.contract_amount = contract_amount
    
    def calculate_pay(self):
        return self.contract_amount
    
    def get_benefits(self):
        return ["None"]

class EmployeeFactory:
    @staticmethod
    def create_employee(emp_type, name, employee_id, *args):
        if emp_type == EmployeeType.FULL_TIME:
            return FullTimeEmployee(name, employee_id, args[0])
        elif emp_type == EmployeeType.PART_TIME:
            return PartTimeEmployee(name, employee_id, args[0], args[1])
        elif emp_type == EmployeeType.CONTRACT:
            return ContractEmployee(name, employee_id, args[0])
        else:
            raise ValueError(f"Unknown employee type: {emp_type}")

class PayrollSystem:
    def __init__(self):
        self.employees = []
    
    def add_employee(self, employee):
        self.employees.append(employee)
    
    def process_payroll(self):
        print("\n=== Processing Payroll ===")
        for employee in self.employees:
            pay = employee.calculate_pay()
            benefits = ", ".join(employee.get_benefits())
            print(f"{employee}")
            print(f"  Pay: ${pay:.2f}")
            print(f"  Benefits: {benefits}")
        print(f"\nTotal Employees: {Employee.employee_count}")

# Use the system
payroll = PayrollSystem()

# Create different types of employees using factory
emp1 = EmployeeFactory.create_employee(
    EmployeeType.FULL_TIME, "Alice Johnson", "FT001", 75000
)
emp2 = EmployeeFactory.create_employee(
    EmployeeType.PART_TIME, "Bob Smith", "PT001", 25, 80
)
emp3 = EmployeeFactory.create_employee(
    EmployeeType.CONTRACT, "Charlie Brown", "CT001", 5000
)

payroll.add_employee(emp1)
payroll.add_employee(emp2)
payroll.add_employee(emp3)

payroll.process_payroll()
```

## Key Takeaways

✓ **Inheritance** creates parent-child relationships (is-a relationships)

✓ **`super()`** accesses parent class methods and `__init__`

✓ **Method overriding** replaces parent methods in child classes

✓ **Polymorphism** allows different objects to respond to the same method call differently

✓ **Abstract classes** (ABC) force child classes to implement specific methods

✓ **Multiple inheritance** allows inheriting from multiple parents (use carefully)

✓ **Factory Pattern** creates objects without specifying exact class

✓ **Strategy Pattern** makes algorithms interchangeable

✓ **Observer Pattern** notifies objects about state changes

✓ **Design patterns** solve common programming problems with proven solutions
