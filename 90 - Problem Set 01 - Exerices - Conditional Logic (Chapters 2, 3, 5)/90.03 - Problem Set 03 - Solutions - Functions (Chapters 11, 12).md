## Level 1: Basic Functions (Problems 1-5)

### Problem 1: Simple Greeting

**Thinking Process:**
The simplest function - no parameters, just performs an action. Use `def` to define, indent the code block, then call it by name with parentheses.

**Solution:**
```python
def say_hello():
    print("Hello, World!")

say_hello()
say_hello()
say_hello()
```

**Key Points:**
- `def` keyword starts function definition
- Function name follows variable naming rules
- Empty parentheses `()` means no parameters
- Colon `:` starts the code block
- Indented code is the function body
- Call with `function_name()` - parentheses are required!

## Level 2: Return Values (Problems 6-10)

### Problem 6: Multiply Function

**Thinking Process:**
Now we need to return a value instead of printing. Return sends the value back so we can store it or use it elsewhere.

**Solution:**
```python
def multiply(x, y):
    return x * y

result = multiply(5, 4)
print(result)  # 20
```

**Key Points:**
- `return` sends value back to caller
- We can store the returned value in a variable
- Return vs Print: return gives us the value, print just shows it
- After return executes, function stops

### Problem 9: Find Maximum

**Thinking Process:**
Compare three values. Use if-elif-else to check which is largest, return that value.

**Solution:**
```python
def find_max(a, b, c):
    if a >= b and a >= c:
        return a
    elif b >= a and b >= c:
        return b
    else:
        return c

print(find_max(5, 12, 8))  # 12
```

**Key Points:**
- Check conditions and return appropriate value
- Once return executes, function ends
- Could also use: `return max(a, b, c)` but this shows the logic

## Level 3: Validation and Logic (Problems 11-15)

### Problem 11: Validate Range

**Thinking Process:**
Check if number falls within boundaries. Use `and` to ensure both conditions are true.

**Solution:**
```python
def is_in_range(number, low, high):
    return low <= number <= high

print(is_in_range(5, 1, 10))   # True
print(is_in_range(15, 1, 10))  # False
```

**Key Points:**
- Python allows chained comparisons: `low <= number <= high`
- Returns boolean directly without if/else
- Equivalent to: `return number >= low and number <= high`

### Problem 12: Calculate Discount

**Thinking Process:**
Calculate discount amount, subtract from price. Formula: price - (price × discount/100)

**Solution:**
```python
def apply_discount(price, discount_percent):
    discount_amount = price * (discount_percent / 100)
    new_price = price - discount_amount
    return new_price

print(apply_discount(100, 20))  # 80.0
```

**Key Points:**
- Break calculation into steps for clarity
- Or compact: `return price * (1 - discount_percent / 100)`
- Both approaches give same result

### Problem 15: Count Vowels

**Solution:**

```python
    return count

```

**Key Points:**

## Level 4: Optional Parameters (Problems 16-20)

### Problem 16: Power with Default

**Thinking Process:**
This introduces default parameters. If no exponent provided, use 2. Default parameter must be last.

**Solution:**
```python
def power(base, exponent=2):
    return base ** exponent

print(power(5))      # 25 (uses default: 5²)
print(power(5, 3))   # 125 (overrides default: 5³)
print(power(2, 10))  # 1024
```

**Key Points:**
- `exponent=2` sets default value
- Call with one argument: uses default
- Call with two arguments: overrides default
- Default parameters must come after required parameters

### Problem 19: Format Name

**Thinking Process:**
Optional middle name. Check if middle was provided (not empty string), format accordingly.

**Solution:**
```python
def format_name(first, last, middle=""):
    if middle:
        return f"{first} {middle} {last}"
    else:
        return f"{first} {last}"

print(format_name("John", "Smith"))              # John Smith
print(format_name("John", "Smith", "Michael"))   # John Michael Smith
```

**Key Points:**
- Empty string as default
- `if middle:` checks if middle is not empty
- Different return based on whether middle provided
- Alternative: `return f"{first} {middle} {last}".strip()` handles both

## Level 5: Named Arguments and Complex Logic (Problems 21-22)

### Problem 21: Pizza Order

**Thinking Process:**
Complex calculation with multiple optional parameters. Calculate step by step: base price, add toppings, add delivery, calculate tip on subtotal.

**Solution:**
```python
def order_pizza(size, toppings=1, delivery=False, tip_percent=15):
    # Base price by size
    if size == "Small":
        base_price = 10
    elif size == "Medium":
        base_price = 15
    else:  # Large
        base_price = 20
    
    # Add topping cost
    subtotal = base_price + (toppings * 2)
    
    # Add delivery fee
    if delivery:
        subtotal = subtotal + 5
    
    # Calculate tip
    tip = subtotal * (tip_percent / 100)
    
    # Total
    total = subtotal + tip
    return total

# Using named arguments in different orders
print(order_pizza("Medium"))                                    # 19.55
print(order_pizza("Large", toppings=3, delivery=True))         # 31.05
print(order_pizza(size="Small", delivery=True, tip_percent=20))  # 18.00
```

**Key Points:**
- Named arguments can be in any order
- Must calculate in stages: base → toppings → delivery → tip
- Boolean parameter for yes/no options (delivery)
- Named arguments make complex calls readable

## Level 6: Recursion (Problems 23-25)

### Problem 23: Recursive Countdown

**Thinking Process:**
This is the introduction to recursion. Base case: stop at 0. Recursive case: print current number, call with n-1. Each call gets closer to base case.

**Solution:**
```python
def countdown(n):
    if n <= 0:
        print("Blastoff!")
    else:
        print(n)
        countdown(n - 1)

countdown(5)
```

**Output:**
```
5
4
3
2
1
Blastoff!
```

**Key Points:**
- Base case: `n <= 0` stops recursion
- Recursive case: print then call with smaller n
- Progress toward base: n decreases each call
- Stack of calls: countdown(5) → countdown(4) → countdown(3) → ... → countdown(0)

---

### Problem 24: Factorial with Validation

**Thinking Process:**
Combine recursion with optional parameter and validation. Base case for n≤1, recursive case multiplies n by factorial(n-1). Optional parameter controls whether to show steps.

**Solution:**
```python
def factorial(n, show_steps=False):
    # Validation
    if n < 0:
        return "Invalid input"
    
    # Base case
    if n == 0 or n == 1:
        if show_steps:
            print(f"Base case: {n}! = 1")
        return 1
    
    # Recursive case
    if show_steps:
        print(f"Calculating {n}! = {n} × {n-1}!")
    
    result = n * factorial(n - 1, show_steps)
    
    if show_steps:
        print(f"{n}! = {result}")
    
    return result

print(factorial(5))                 # 120
print(factorial(5, show_steps=True))  # Shows all steps
print(factorial(-3))                # Invalid input
```

**Key Points:**
- Check for invalid input first
- Base case prevents infinite recursion
- Recursive case: n × factorial(n-1)
- Optional parameter controls extra behavior without changing core logic
- Each recursive call passes the show_steps parameter through

**How factorial(5) works:**
```
factorial(5)
= 5 × factorial(4)
= 5 × (4 × factorial(3))
= 5 × (4 × (3 × factorial(2)))
= 5 × (4 × (3 × (2 × factorial(1))))
= 5 × (4 × (3 × (2 × 1)))
= 120
```

### Problem 25: Advanced Fibonacci

**Thinking Process:**
Most complex problem - recursion with tuple as optional parameter. Need to handle custom starting values for base cases, then recursive formula for n≥2.

**Solution:**
```python
def fibonacci(n, starting_values=(0, 1)):
    # Extract starting values from tuple
    fib_0 = starting_values[0]
    fib_1 = starting_values[1]
    
    # Base cases use custom starting values
    if n == 0:
        return fib_0
    if n == 1:
        return fib_1
    
    # Recursive case: sum of previous two
    return fibonacci(n - 1, starting_values) + fibonacci(n - 2, starting_values)

# Standard Fibonacci
print(fibonacci(0))     # 0
print(fibonacci(1))     # 1
print(fibonacci(5))     # 5
print(fibonacci(10))    # 55

# Custom starting values
print(fibonacci(5, (2, 3)))  # Sequence: 2, 3, 5, 8, 13 → returns 13
print(fibonacci(6, (1, 1)))  # Sequence: 1, 1, 2, 3, 5, 8 → returns 8
```

**Key Points:**
- Tuple parameter allows custom starting values
- Access tuple elements: `starting_values[0]` and `starting_values[1]`
- Base cases return appropriate starting value
- Recursive case passes starting_values to maintain consistency
- Must pass starting_values in recursive calls so custom values persist

**How it works with starting_values=(2, 3):**
```
fibonacci(5, (2,3))
= fibonacci(4, (2,3)) + fibonacci(3, (2,3))
= (fib(3) + fib(2)) + (fib(2) + fib(1))
= ((fib(2) + fib(1)) + (fib(1) + fib(0))) + ((fib(1) + fib(0)) + 3)
= ((3 + 3) + (3 + 2)) + ((3 + 2) + 3)
= (6 + 5) + (5 + 3)
= 11 + 8
Wait, let me recalculate:

Position 0: 2
Position 1: 3
Position 2: 2+3 = 5
Position 3: 3+5 = 8
Position 4: 5+8 = 13
Position 5: 8+13 = 21

So fibonacci(5, (2,3)) = 21
```

**This problem combines:**
- Recursion (function calling itself)
- Optional parameters (default tuple)
- Tuple unpacking (extracting values)
- Base cases with dynamic values
- Maintaining state through recursive calls

## Key Takeaways from Solutions

### Function Fundamentals:
1. **Define before use** - Python must see definition first
2. **Parameters vs Arguments** - parameters in definition, arguments when calling
3. **Return vs Print** - return sends value back, print just displays

### Parameter Patterns:
4. **Positional arguments** - order matters
5. **Named arguments** - order doesn't matter, must come after positional
6. **Default parameters** - make arguments optional, must be last

### Return Patterns:
7. **Direct boolean return** - `return condition` instead of if/else
8. **Early returns** - return immediately when condition met
9. **Multiple return paths** - different returns for different cases

### Recursion Essentials:
10. **Base case** - condition that stops recursion
11. **Recursive case** - function calls itself with modified input
12. **Progress** - must move toward base case each call
13. **State preservation** - pass values through recursive calls if needed

### Advanced Techniques:
14. **Optional parameters replace overloading** - one flexible function instead of many
15. **Named arguments improve readability** - especially with many parameters
16. **Tuples as parameters** - can pass multiple related values as one parameter
17. **Combine recursion with defaults** - optional behavior in recursive functions

## Common Pitfalls and Solutions

### Pitfall 1: Calling without Parentheses
```python
def greet():
    print("Hello")

greet    # Wrong - just references the function
greet()  # Correct - calls the function
```

### Pitfall 2: Forgetting to Return
```python
def add(a, b):
    a + b  # Wrong - calculates but doesn't return

def add(a, b):
    return a + b  # Correct
```

### Pitfall 3: Default Not Last
```python
def func(a=5, b):  # Wrong - default not last
    pass

def func(b, a=5):  # Correct - default at end
    pass
```

### Pitfall 4: No Base Case in Recursion
```python
def countdown(n):
    print(n)
    countdown(n - 1)  # Wrong - runs forever!

def countdown(n):
    if n <= 0:      # Correct - base case stops it
        return
    print(n)
    countdown(n - 1)
```
