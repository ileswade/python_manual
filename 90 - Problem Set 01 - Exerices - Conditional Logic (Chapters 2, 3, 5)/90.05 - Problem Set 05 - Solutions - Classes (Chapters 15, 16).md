## Level 1: Basic Class Structure (Problems 1-5)

### Problem 1: Empty Class

**Thinking Process:**
The simplest possible class - just the structure. This demonstrates that a class is just a template, even if it's empty.

**Solution:**
```python
class EmptyBox:
    pass  # 'pass' means "do nothing"

# Create an instance
box = EmptyBox()
print(type(box))  # <class '__main__.EmptyBox'>
```

**Key Points:**
- `pass` is a placeholder when you need a code block but have nothing to put in it
- You can still create objects from an empty class
- `type()` shows what class the object came from
- This proves: class = template, even if empty

### Problem 2: Class with One Variable

**Thinking Process:**
Now we add `__init__` - the initializer that runs when creating objects. We store one piece of data.

**Solution:**
```python
class SimpleCounter:
    def __init__(self):
        self.count = 0

# Create instance and access variable
counter = SimpleCounter()
print(counter.count)  # 0
```

**Key Points:**
- `__init__` always takes `self` as first parameter
- `self.count = 0` stores data in the object
- Access with dot notation: `object.variable`
- Every new counter starts at 0

### Problem 3: Class with Multiple Variables

**Thinking Process:**
Now `__init__` takes parameters. Values passed when creating object become instance variables.

**Solution:**
```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

# Create point
point = Point(5, 10)
print(f"x: {point.x}, y: {point.y}")  # x: 5, y: 10
```

**Key Points:**
- Parameters after `self` are values needed to create object
- `self.x = x` stores the parameter in the instance
- Call like function: `Point(5, 10)` passes 5 to x, 10 to y

### Problem 4: Multiple Instances

**Thinking Process:**
Create multiple objects from same template. Each has its own data - they don't share values.

**Solution:**
```python
class Color:
    def __init__(self, red, green, blue):
        self.red = red
        self.green = green
        self.blue = blue

# Create different colors
color1 = Color(255, 0, 0)      # Red
color2 = Color(0, 255, 0)      # Green
color3 = Color(0, 0, 255)      # Blue

print(f"Color 1: R={color1.red}, G={color1.green}, B={color1.blue}")
print(f"Color 2: R={color2.red}, G={color2.green}, B={color2.blue}")
print(f"Color 3: R={color3.red}, G={color3.green}, B={color3.blue}")
```

**Key Points:**
- Same class, different data
- Each object independent - changing one doesn't affect others
- This is the power of classes: one template, many instances

## Level 3: Modifying State (Problems 11-15)

### Problem 11: Increment Counter

**Thinking Process:**
Now methods MODIFY the object's data. This changes the object's state.

**Solution:**
```python
class Counter:
    def __init__(self):
        self.value = 0
    
    def increment(self):
        self.value = self.value + 1
    
    def get_value(self):
        return self.value

# Use it
counter = Counter()
print(counter.get_value())  # 0
counter.increment()
counter.increment()
print(counter.get_value())  # 2
```

**Key Points:**
- `self.value = self.value + 1` modifies state
- State persists between method calls
- `get_value()` retrieves current state

### Problem 13: Traffic Light

**Thinking Process:**
State can be string values. Method changes state based on current value - conditional state changes.

**Solution:**
```python
class TrafficLight:
    def __init__(self):
        self.color = "red"
    
    def change(self):
        if self.color == "red":
            self.color = "green"
        elif self.color == "green":
            self.color = "yellow"
        else:
            self.color = "red"
    
    def get_color(self):
        return self.color

# Use it
light = TrafficLight()
print(light.get_color())  # red
light.change()
print(light.get_color())  # green
light.change()
print(light.get_color())  # yellow
```

**Key Points:**
- State determines next state (state machine pattern)
- Check current state, set new state
- Cycles through values

### Problem 14: Inventory Item

**Thinking Process:**
Methods can validate before modifying. Check if operation is valid before changing state.

**Solution:**
```python
class Product:
    def __init__(self, name, quantity):
        self.name = name
        self.quantity = quantity
    
    def restock(self, amount):
        self.quantity = self.quantity + amount
    
    def sell(self, amount):
        if amount <= self.quantity:
            self.quantity = self.quantity - amount
        else:
            print(f"Not enough {self.name} in stock!")
    
    def in_stock(self):
        return self.quantity > 0

# Use it
product = Product("Widget", 10)
product.sell(3)
print(f"Quantity: {product.quantity}")  # 7
product.sell(10)  # Not enough Widget in stock!
```

**Key Points:**
- Check condition before modifying: `if amount <= self.quantity`
- Protect data integrity with validation
- Multiple methods work together

### Problem 15: Temperature Tracker

**Thinking Process:**
Instance variable can be a list. Methods add to list and calculate from it.

**Solution:**
```python
class TemperatureLog:
    def __init__(self):
        self.temperatures = []
    
    def add_reading(self, temp):
        self.temperatures.append(temp)
    
    def average(self):
        if len(self.temperatures) == 0:
            return 0
        return sum(self.temperatures) / len(self.temperatures)
    
    def count(self):
        return len(self.temperatures)

# Use it
log = TemperatureLog()
log.add_reading(20)
log.add_reading(22)
log.add_reading(19)

print(f"Average: {log.average():.1f}")  # Average: 20.3
print(f"Readings: {log.count()}")       # Readings: 3
```

**Key Points:**
- `self.temperatures = []` creates empty list
- `.append()` adds to the list
- Check for empty list before calculating average

## Level 4: Working with State (Problems 16-20)

### Problem 16: Shopping Cart

**Thinking Process:**
Store list of dictionaries. Each dict is an item. Methods manipulate this complex structure.

**Solution:**
```python
class ShoppingCart:
    def __init__(self):
        self.items = []
    
    def add_item(self, name, price, qty):
        item = {
            "name": name,
            "price": price,
            "quantity": qty
        }
        self.items.append(item)
    
    def total(self):
        total = 0
        for item in self.items:
            total += item["price"] * item["quantity"]
        return total
    
    def item_count(self):
        return len(self.items)

# Use it
cart = ShoppingCart()
cart.add_item("Apple", 1.99, 5)
cart.add_item("Banana", 0.99, 3)

print(f"Items: {cart.item_count()}")  # Items: 2
print(f"Total: ${cart.total():.2f}")  # Total: $12.92
```

**Key Points:**
- Create dict inside method, append to list
- Iterate list of dicts to calculate
- Access dict values: `item["price"]`

### Problem 17: Grade Book

**Thinking Process:**
Combine list storage with calculation methods. Average depends on current list contents.

```python
class GradeBook:
    def __init__(self, student_name):

            return "B"
        elif avg >= 70:
            return "C"
        elif avg >= 60:
            return "D"

            return "F"

# Use it
grades = GradeBook("Alice")

grades.add_grade(90)
grades.add_grade(92)

```

**Key Points:**

### Problem 18: Playlist Manager

**Thinking Process:**
Methods add, remove, count, and check membership. String list manipulation.

**Solution:**
```python
class Playlist:
    def __init__(self, name):
        self.name = name
        self.songs = []
    
    def add_song(self, song_name):
        self.songs.append(song_name)
    
    def remove_song(self, song_name):

playlist = Playlist("My Favorites")

playlist.add_song("Song C")

```

**Key Points:**
- `.remove()` removes first occurrence
- Check existence: `in self.songs`

### Problem 19: Task List

**Thinking Process:**
Store complex dicts (with multiple fields). Modify dict values based on criteria.

**Solution:**
```python
class TaskList:
    def __init__(self):
        self.tasks = []
    
    def add_task(self, description):
        task = {
            "description": description,
            "completed": False
        }
        self.tasks.append(task)
    
    def complete_task(self, description):
        for task in self.tasks:
            if task["description"] == description:
                task["completed"] = True
                break
    
    def remaining(self):
        count = 0
        for task in self.tasks:
            if not task["completed"]:
                count += 1
        return count

# Use it
tasks = TaskList()
tasks.add_task("Buy groceries")
tasks.add_task("Clean room")
tasks.add_task("Study Python")

print(f"Remaining: {tasks.remaining()}")  # Remaining: 3
tasks.complete_task("Buy groceries")
print(f"Remaining: {tasks.remaining()}")  # Remaining: 2
```

**Key Points:**
- Modify dict in list: `task["completed"] = True`
- Search list for matching dict
- Count based on condition

### Problem 20: Score Tracker

**Thinking Process:**
Methods that add, subtract, reset. Protect against negative values.

**Solution:**
```python
class Game:
    def __init__(self, player_name):
        self.player_name = player_name
        self.score = 0
    
    def add_points(self, points):
        self.score += points
    
    def subtract_points(self, points):
        self.score -= points
        if self.score < 0:
            self.score = 0
    
    def reset(self):
        self.score = 0
    
    def get_score(self):
        return self.score

# Use it
game = Game("Alice")
game.add_points(100)
game.add_points(50)
print(f"Score: {game.get_score()}")  # Score: 150
game.subtract_points(200)
print(f"Score: {game.get_score()}")  # Score: 0 (protected)
```

**Key Points:**
- Check after subtraction: minimum 0
- Reset to initial state
- Multiple ways to modify same variable

```python
class Account:
```

### Problem 25: Complete Shopping System

**Thinking Process:**
Most complex: list of dicts, multiple calculations, formatted output, both special methods.

**Solution:**
```python
class Order:
    def __init__(self, order_id):
        self.order_id = order_id
        self.items = []
    
    def add_item(self, name, price, qty):
        item = {
            "name": name,
            "price": price,
            "quantity": qty
        }
        self.items.append(item)
    
    def remove_item(self, name):
        self.items = [item for item in self.items if item["name"] != name]
    
    def subtotal(self):
        total = 0
        for item in self.items:
            total += item["price"] * item["quantity"]
        return total
    
    def tax(self, rate):
        return self.subtotal() * rate
    
    def total(self, tax_rate):
        return self.subtotal() + self.tax(tax_rate)
    
    def __str__(self):
        item_count = len(self.items)
        total_amount = self.total(0.05)
        return f"Order #{self.order_id}\nItems: {item_count}\nTotal: ${total_amount:.2f}"
    
    def __repr__(self):
        return f"Order('{self.order_id}', {len(self.items)} items)"

# Use it
order = Order("12345")
order.add_item("Widget", 10.99, 2)
order.add_item("Gadget", 5.99, 3)

print(order)
print(repr(order))
```

**Key Points:**
- Methods call other methods: `total()` calls `subtotal()` and `tax()`
- List comprehension for removal: `[item for item in self.items if ...]`
- Multi-line `__str__` with `\n`
- Complete system bringing all concepts together

## Key Takeaways from Solutions

### Class Structure Progression:
1. **Empty class** - just template
2. **Store data** - `__init__` with `self.variable`
3. **Add methods** - functions using `self`
4. **Modify state** - methods changing data
5. **Complex state** - lists, dicts
6. **Special methods** - `__str__`, `__repr__`

### `self` Understanding:
- Always first parameter in methods
- Refers to specific object
- Access data: `self.variable`
- Modify data: `self.variable = new_value`

### Method Patterns:
- **Getters**: Return data (`get_value()`)
- **Setters**: Modify data (`set_value(x)`)
- **Calculations**: Compute from data (`average()`)
- **Actions**: Do something (`deposit(amount)`)
- **Checks**: Return boolean (`is_passing()`)

### Special Methods:
- `__str__`: User-friendly string
- `__repr__`: Developer representation
- Both return strings (don't print)
