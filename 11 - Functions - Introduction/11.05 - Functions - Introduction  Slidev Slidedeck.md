# Why Functions? 🔧

Functions are like **tools** - reusable pieces of code that perform specific tasks. Instead of writing the same code over and over, you create a function once and use it everywhere!

<v-clicks>

- 🔄 **Avoid repetition** - write once, use many times
- 📦 **Organization** - break complex problems into smaller pieces
- 🐛 **Easier debugging** - fix bugs in one place
- 🧪 **Testing** - test individual pieces separately
- 👥 **Collaboration** - share code with others

</v-clicks>

# What is a Function? 📦

A **function** is a named block of code that performs a specific task. Think of it as a machine that takes input, does something, and optionally gives you output.

<v-clicks>

### Basic Function Structure

```python
def function_name():
    # Code to execute
    print("Hello from inside the function!")

# Call the function
function_name()
```

**Key parts:**
- `def` keyword to define a function
- Function name (like variable names, use descriptive names)
- Parentheses `()` (may contain parameters)
- Colon `:` to start the function body
- Indented code block

</v-clicks>

---

# Your First Function 👋

<v-clicks>

```python
def greet():
    print("Hello, world!")
    print("Welcome to functions!")

# Call the function
greet()
```

**Output:**
```
Hello, world!
Welcome to functions!
```

### Multiple Calls

```python
def greet():
    print("Hello, world!")

greet()  # First call
greet()  # Second call
greet()  # Third call
```

Each call executes the function's code again!

</v-clicks>

# Functions with Parameters 📥

**Parameters** let you pass data INTO functions, making them more flexible:

<v-clicks>

```python
def greet(name):
    print(f"Hello, {name}!")
    print("Welcome to functions!")

# Call with different arguments
greet("Alice")    # Hello, Alice!
greet("Bob")      # Hello, Bob!
greet("Charlie")  # Hello, Charlie!
```

**Terminology:**
- **Parameter**: `name` in the function definition
- **Argument**: `"Alice"` when calling the function

</v-clicks>

<v-click>

Parameters make functions **reusable** with different data!

</v-click>

# Multiple Parameters 📊

Functions can accept multiple parameters:

<v-clicks>

```python
def add_numbers(a, b):
    result = a + b
    print(f"{a} + {b} = {result}")

# Call with different arguments
add_numbers(5, 3)    # 5 + 3 = 8
add_numbers(10, 7)   # 10 + 7 = 17
add_numbers(2, 9)    # 2 + 9 = 11
```

```python
def introduce_person(name, age, city):
    print(f"Hi, I'm {name}")
    print(f"I'm {age} years old")
    print(f"I live in {city}")

introduce_person("Alice", 25, "Toronto")
```

**Important:** Arguments must be passed in the same order as parameters!

</v-clicks>

# Return Values: Getting Output 📤

Use `return` to send data back from a function:

<v-clicks>

```python
def add_numbers(a, b):
    result = a + b
    return result

# Capture the returned value
sum_result = add_numbers(5, 3)
print(sum_result)  # 8

# Or use directly
print(add_numbers(10, 7))  # 17
```

### Without Return vs With Return

```python
def print_sum(a, b):        def calculate_sum(a, b):
    result = a + b              result = a + b
    print(result)               return result

print_sum(5, 3)             answer = calculate_sum(5, 3)
# Just prints                # Can store and reuse!
```

</v-clicks>

# Return vs Print: Key Difference 🔍

<div class="grid grid-cols-2 gap-6">

<div>

<v-click>

### Function that PRINTS
```python
def greet(name):
    print(f"Hello, {name}!")

greet("Alice")  # Prints to console
result = greet("Alice")
print(result)   # None
```

**Prints directly to console, returns `None`**

</v-click>

</div>

<div>

<v-click>

### Function that RETURNS
```python
def greet(name):
    return f"Hello, {name}!"

message = greet("Alice")
print(message)  # Hello, Alice!
print(greet("Bob"))  # Hello, Bob!
```

**Returns data you can store/use**

</v-click>

</div>

</div>

<v-click>

### When to Use Each

**Use return when:**
- You need the result for further calculations
- Building reusable components
- Testing functions

**Use print when:**
- Displaying information to users
- Debugging
- Final output of your program

</v-click>

# Variable Scope: Local vs Global 🌍

**Scope** determines where variables can be accessed:

<v-clicks>

### Local Variables (Inside Functions)

```python
def my_function():
    local_var = "I'm local!"
    print(local_var)

my_function()  # I'm local!
print(local_var)  # ERROR! Variable doesn't exist here
```

**Local variables only exist inside their function**

### Global Variables (Outside Functions)

```python
global_var = "I'm global!"

def my_function():
    print(global_var)  # Can READ global variables

my_function()  # I'm global!
print(global_var)  # I'm global!
```

</v-clicks>

---

# Scope Rules and Examples 📏

<v-clicks>

```python
name = "Global Alice"  # Global variable

def greet():
    name = "Local Bob"  # Local variable (shadows global)
    print(f"Inside function: {name}")

def greet_global():
    print(f"Using global: {name}")  # Uses global variable

greet()         # Inside function: Local Bob
greet_global()  # Using global: Global Alice
print(f"Outside: {name}")  # Outside: Global Alice
```

**Key rules:**
1. Local variables are created inside functions
2. Local variables "shadow" (hide) global ones with the same name
3. Functions can read global variables
4. Functions create new local variables when assigned

</v-clicks>

<v-click>

**Best practice:** Use parameters instead of global variables when possible!

</v-click>

---

# Modifying Global Variables 🔄

<v-clicks>

To modify a global variable inside a function, use the `global` keyword:

```python
counter = 0  # Global variable

def increment():
    global counter  # Tell Python we want to modify the global
    counter += 1

def reset():
    global counter
    counter = 0

print(f"Counter: {counter}")  # Counter: 0
increment()
print(f"Counter: {counter}")  # Counter: 1
increment()
print(f"Counter: {counter}")  # Counter: 2
reset()
print(f"Counter: {counter}")  # Counter: 0
```

**Use sparingly!** Usually better to return values and pass parameters.

</v-clicks>

# Functions Calling Functions 📞

Functions can call other functions:

<v-clicks>

```python
def get_name():
    return input("Enter your name: ")

def get_age():
    return int(input("Enter your age: "))

def create_greeting(name, age):
    return f"Hello {name}, you are {age} years old!"

def main():
    name = get_name()
    age = get_age()
    message = create_greeting(name, age)
    print(message)

# Run the program
main()
```

This creates a clear flow: `main()` → `get_name()` → `get_age()` → `create_greeting()`

</v-clicks>

<v-click>

Breaking code into small functions makes it easier to understand and debug!

</v-click>

# Introduction to Recursion 🔄

**Recursion** is when a function calls itself. It's like a loop, but using function calls:

<v-clicks>

### Simple Recursive Example

```python
def countdown(n):
    if n <= 0:
        print("Blast off!")
    else:
        print(n)
        countdown(n - 1)  # Function calls itself!

countdown(5)
```

**Output:**
```
5
4
3
2
1
Blast off!
```

</v-clicks>

---

# How Recursion Works 🎯

<v-clicks>

**Two essential parts:**
1. **Base case** - condition to stop recursion
2. **Recursive case** - function calls itself with modified input

```python
def countdown(n):
    # Base case - stop here!
    if n <= 0:
        print("Blast off!")
    else:
        # Recursive case - call yourself
        print(n)
        countdown(n - 1)  # Getting closer to base case
```

**What happens:**
- `countdown(3)` prints 3, calls `countdown(2)`
- `countdown(2)` prints 2, calls `countdown(1)`
- `countdown(1)` prints 1, calls `countdown(0)`
- `countdown(0)` prints "Blast off!" and stops

</v-clicks>

<v-click>

**Without base case:** Infinite recursion! (Stack overflow error)

</v-click>

---

# Practical Recursion: Factorial 🔢

**Factorial** of n (written n!) = n × (n-1) × (n-2) × ... × 1

<v-clicks>

### Mathematical Definition
- 5! = 5 × 4 × 3 × 2 × 1 = 120
- 3! = 3 × 2 × 1 = 6
- 1! = 1
- 0! = 1 (by definition)

### Recursive Pattern
- 5! = 5 × 4!
- 4! = 4 × 3!
- 3! = 3 × 2!
- 2! = 2 × 1!
- 1! = 1 (base case)

</v-clicks>

---

# Factorial Implementation 📝

<v-clicks>

```python
def factorial(n):
    # Base case
    if n <= 1:
        return 1
    else:
        # Recursive case
        return n * factorial(n - 1)

# Test the function
print(factorial(5))  # 120
print(factorial(3))  # 6
print(factorial(1))  # 1
print(factorial(0))  # 1
```

**How `factorial(4)` works:**
- `factorial(4)` returns `4 * factorial(3)`
- `factorial(3)` returns `3 * factorial(2)`
- `factorial(2)` returns `2 * factorial(1)`
- `factorial(1)` returns `1`
- Final result: `4 * 3 * 2 * 1 = 24`

</v-clicks>

---

# Recursion vs Loops 🔄

<div class="grid grid-cols-2 gap-6">

<div>

<v-click>

### Recursive Solution
```python
def factorial(n):
    if n <= 1:
        return 1
    else:
        return n * factorial(n - 1)

print(factorial(5))  # 120
```

**Pros:** Elegant, matches mathematical definition
**Cons:** Can be slower, uses more memory

</v-click>

</div>

<div>

<v-click>

### Loop Solution
```python
def factorial(n):
    result = 1
    for i in range(1, n + 1):
        result *= i
    return result

print(factorial(5))  # 120
```

**Pros:** Faster, uses less memory
**Cons:** Less intuitive for some problems

</v-click>

</div>

</div>

<v-click>

**When to use recursion:**
- Problem naturally breaks down into smaller versions
- Mathematical definitions (factorial, Fibonacci)
- Tree/graph traversal (later courses)

**When to use loops:**
- Simple counting or iteration
- Performance is critical
- Memory usage matters

</v-click>

# Common Recursion Mistakes ⚠️

<v-clicks>

### 1. Missing Base Case
```python
def bad_countdown(n):
    print(n)
    bad_countdown(n - 1)  # Never stops!
```

**Result:** Stack overflow error (infinite recursion)

### 2. Base Case Never Reached
```python
def bad_function(n):
    if n == 0:
        return 1
    else:
        return n * bad_function(n + 1)  # Getting FURTHER from 0!
```

### 3. Forgetting to Return
```python
def bad_factorial(n):
    if n <= 1:
        return 1
    else:
        n * bad_factorial(n - 1)  # Missing return!
```

</v-clicks>

# Best Practices for Functions ✅

<v-clicks>

### 1. Use Descriptive Names
```python
# ❌ Bad
def calc(x, y):
    return x + y

# ✅ Good
def calculate_total_price(base_price, tax):
    return base_price + tax
```

### 2. One Task Per Function
```python
# ❌ Too much in one function
def process_student():
    name = input("Name: ")
    grade = int(input("Grade: "))
    average = (grade + 85 + 92) / 3
    if average >= 60:
        print(f"{name} passes with {average:.1f}")
    else:
        print(f"{name} fails with {average:.1f}")

# ✅ Split into focused functions
def get_student_name():
    return input("Name: ")

def calculate_average(grades):
    return sum(grades) / len(grades)
```

</v-clicks>

---

# More Best Practices 📋

<v-clicks>

### 3. Use Return Values
```python
# ❌ Hard to test and reuse
def check_password(password):
    if len(password) >= 8:
        print("Password is strong")
    else:
        print("Password is weak")

# ✅ Return values for flexibility
def is_strong_password(password):
    return len(password) >= 8

password = "mypassword"
if is_strong_password(password):
    print("Password is strong")
else:
    print("Password is weak")
```

### 4. Keep Functions Short
- Generally 5-20 lines
- If longer, consider breaking into smaller functions
- Each function should do ONE thing well

</v-clicks>

# Practical Example: Grade Calculator 📊

<v-clicks>

```python
def get_student_grades():
    """Get grades from user input"""
    grades = []
    while True:
        grade_input = input("Enter grade (or 'done' to finish): ")
        if grade_input.lower() == 'done':
            break
        try:
            grade = float(grade_input)
            grades.append(grade)
        except ValueError:
            print("Invalid grade, please try again")
    return grades

def calculate_average(grades):
    """Calculate average of a list of grades"""
    if len(grades) == 0:
        return 0
    return sum(grades) / len(grades)

def get_letter_grade(average):
    """Convert numeric average to letter grade"""
    if average >= 90:
        return 'A'
    elif average >= 80:
        return 'B'
    elif average >= 70:
        return 'C'
    elif average >= 60:
        return 'D'
    else:
        return 'F'
```

</v-clicks>

# Grade Calculator (continued) 📝

<v-clicks>

```python
def display_results(grades, average, letter):
    """Display the final results"""
    print(f"\nGrades entered: {grades}")
    print(f"Average: {average:.2f}")
    print(f"Letter grade: {letter}")

def main():
    """Main program function"""
    print("Grade Calculator")
    print("-" * 20)

    grades = get_student_grades()
    if len(grades) == 0:
        print("No grades entered!")
        return

    average = calculate_average(grades)
    letter = get_letter_grade(average)
    display_results(grades, average, letter)

# Run the program
if __name__ == "__main__":
    main()
```

Each function has a single, clear purpose!

</v-clicks>
